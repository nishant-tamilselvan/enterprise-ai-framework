# EU AI Act mapping

This page provides architecture traceability for Regulation (EU) 2024/1689. Applicability depends on role, system classification, jurisdiction, dates of application, and evolving implementing guidance. Obtain legal advice.

| Regulatory topic | Framework alignment | Example evidence |
| --- | --- | --- |
| Roles and classification | Inventory, context record, risk tiering, supplier model | Role determination, classification rationale |
| Prohibited practices | Prohibited-use policy and intake gate | Screening decision, policy enforcement records |
| Risk management | Continuous risk process and lifecycle gates | Risk plan, test evidence, residual-risk decision |
| Data and data governance | Information context and data protection lifecycle | Provenance, quality analysis, representativeness checks |
| Technical documentation | Architecture decision and traceability records | System description, versions, dependencies, limitations |
| Record-keeping | Audit and evidence service | Logging design, retention schedule, integrity controls |
| Transparency | User information, output labeling, intended-use constraints | Instructions, notices, generated-content controls |
| Human oversight | Oversight design and consequential action gates | Role design, competence, escalation and override tests |
| Accuracy, robustness, cybersecurity | Evaluation, SLOs, threat model, resilience | Test reports, security assessment, production metrics |
| Post-market monitoring | Operational monitoring and incident governance | Monitoring plan, complaints, incidents, corrective actions |

Do not infer legal classification or conformity from this table. Validate against the official consolidated text, delegated and implementing acts, harmonized standards, codes of practice, and regulator guidance applicable at the time of use.
