# Security Policy

## Supported versions

Maintainers apply security and safety corrections to the latest published version and the current `master` branch. Older documentation releases may remain unchanged.

## Reporting a vulnerability

Report privately through GitHub for information that could enable exploitation, expose sensitive data, or create immediate AI safety risk. Open the repository's **Security** tab and select **Report a vulnerability**, or go straight to the [private report form](https://github.com/nishant-tamilselvan/enterprise-ai-framework/security/advisories/new). Only you and the maintainers can see the report. Reserve public issues for reports that carry none of these risks.

If the private form is unavailable, open a [security contact request](https://github.com/nishant-tamilselvan/enterprise-ai-framework/issues/new?template=security-contact-request.md). The issue is public, so include no details of the problem. A maintainer replies on the issue with a private channel for the report.

Include:

- affected document, workflow, configuration, or version;
- potential impact and affected parties;
- reproduction or validation details that are safe to share;
- suggested mitigation, if known; and
- whether coordinated disclosure constraints apply.

A maintainer will acknowledge a complete report within five business days and provide status updates as investigation proceeds. Timelines depend on severity, validation complexity, and coordination needs.

## Scope

Reports may cover repository automation, dependency or publishing risks, unsafe architectural guidance, exposed secrets, vulnerable reference configurations, and material omissions that could foreseeably weaken deployed systems.

This repository has no bug bounty or guaranteed compensation program. Test only systems for which you have explicit authorization.
